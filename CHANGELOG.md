# Changelog

All notable changes to this project will be documented in this file.

The format is based on [Keep a Changelog](https://keepachangelog.com/en/1.0.0/),
and this project adheres to [Semantic Versioning](https://semver.org/spec/v2.0.0.html).

## [v1.1.0] - 2026-11-17

### Added

- `tags_common` variable (project tagging convention); `tags` is kept as a deprecated alias merged after it
- `ManagedBy = "Terraform"` tag on every taggable resource
- Optional `name` attribute in `replication_groups`, `clusters`, `serverless_caches`, `subnet_groups`, `parameter_groups`, `user_groups` and `global_replication_groups` to override the generated name
- `clusters.replication_group_id` / `clusters.replication_group_key` to attach a read replica cluster to a replication group (engine, node type, port, groups and snapshot settings are inherited and set to `null`)
- `clusters` attributes `availability_zone`, `outpost_mode`, `preferred_outpost_arn`, `snapshot_arns` and `log_delivery_configuration` (standalone Redis/Valkey)
- `replication_groups.global_replication_group_id` to create secondary members of a global datastore (engine, engine version, node type, encryption, parameter group, shard count and snapshot restore are inherited and set to `null`)
- `timeouts` attribute for replication groups, clusters and serverless caches
- Outputs `replication_group_names`, `cluster_names` and `serverless_cache_names`; `global_replication_group_id` in the `replication_groups` output and `replication_group_id` in the `clusters` output
- Region prefixes for `ap-southeast-5`, `ap-southeast-6`, `ap-southeast-7`, `ap-east-2` and `mx-central-1`
- Validations: `auth_token` requires `transit_encryption_enabled`; automatic failover / multi-AZ require `num_cache_clusters >= 2` when set; `node_type` is required except for global secondary members and replica clusters; `replication_group_id` and `replication_group_key` are mutually exclusive; explicit names respect AWS length limits
- Examples `serverless` (Valkey serverless cache) and `valkey-acl` (Valkey replication group with ACL users, user group and a read replica cluster)
- README for each example

### Changed

- Generated cluster IDs are truncated to 50 characters and replication group IDs / serverless cache names to 40 (AWS limits), never ending with a hyphen. Names that fit the limits are unchanged
- `node_type` is now optional in `replication_groups` and `clusters` (still required by validation in the cases where AWS needs it)
- Variable validation error messages translated to Spanish (project convention)
- Example version files renamed from `0-versions.tf` to `versions.tf`; unused `vpc_id` example variable removed; examples use `tags_common`
- `redis-cluster` example now creates a CloudWatch log group and delivers the slow log to it (as its description already stated)
- README rewritten: `source` pinned with `?ref=<tag>`, inputs/outputs match the code, serverless cache name prefix (`sc-`) corrected, global datastore usage documented

### Deprecated

- `tags` variable: use `tags_common`

### Upgrade notes

- Adding the `ManagedBy` tag is an in-place tag update on every resource; no resource is replaced
- Names generated by previous versions are unchanged unless they exceeded the AWS limits (those could not be created before)

## [v1.0.5] - 2026-10-27

### Changed

- Use minimum-only version constraints in the reusable module: AWS provider `~> 6.0` -> `>= 6.0`
- Set module `required_version` to `>= 1.3` (was `~> 1.0`): the module uses `optional()` object type attributes, introduced in Terraform 1.3
- Example root modules keep pessimistic `~>` constraints (AWS provider `~> 6.0`, Terraform `~> 1.3`)
- Update requirements in README accordingly

## [v1.0.2] - 2026-02-28

### Fixed

- Replace `coalesce()` with conditional expressions for `parameter_group_name`, `subnet_group_name` and `user_group_id` cross-references in cluster, replication group and serverless resources (`coalesce()` errors when all arguments are null)
- Shorten serverless cache name prefix from `cache-` to `sc-` to stay within the AWS 40-character limit for serverless cache names

## [v1.0.1] - 2026-02-27

### Fixed

- Use lowercase `redis` as default engine for the `users` variable (AWS provider deprecated case-insensitive matching for `engine` in `aws_elasticache_user`)

## [v1.0.0] - 2026-02-27

### Added

- ElastiCache replication groups (Redis) with full HA support
  - Automatic failover, multi-AZ, cluster mode
  - At-rest and in-transit encryption
  - AUTH token and Redis ACL (user groups)
  - Log delivery configuration (CloudWatch, Kinesis Firehose)
  - Data tiering support (r6gd nodes)
  - IPv4/IPv6/dual-stack network support
- ElastiCache clusters (Memcached)
  - Single-AZ and cross-AZ modes
  - Configurable node count
- ElastiCache serverless caches
  - Cache usage limits (data storage, ECPU)
  - Daily snapshots
  - KMS encryption
- Subnet groups with for_each pattern
- Parameter groups with dynamic parameters
- Users and user groups (Redis ACL)
- Global replication groups for cross-region replication
- Consistent naming convention: `{region_prefix}-{resource-type}-{account_name}-{project_name}-{key}`
- Region prefix auto-detection for 29 AWS regions
- Three complete examples: redis-basic, redis-cluster, memcached
